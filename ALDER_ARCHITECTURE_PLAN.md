# Alder application architecture implementation plan

## Context

Transform Alder into a standalone reactive R notebook application with humans and coding agents as first-class clients. Node/TypeScript owns documents, persistence, dependency graphs, execution planning, services and process lifecycle; Ark is the sole notebook evaluator, with Alder's R helpers inside it and a separate narrow R analyzer. Ship a dedicated Electron application, the same renderer in browser mode, and complete headless MCP support; ACP and embedded agent orchestration are not part of this implementation. Require an installed compatible R, as explicitly selected by the user: do not bundle an R interpreter or make an R package launch the application.

This plan is the sole detailed target-state specification and supersedes conflicting shipping architecture, product claims and public APIs in README.md, dev/ARCHITECTURE.md and dev/README.md. Repository process/integrity rules remain binding. Current code, tests, help, examples and docs are migration inventory, not future compatibility requirements. No intermediate state is a supported release: completion means the entire Node-owned application, all four clients and all retained capabilities, with every superseded path removed.

## Approach

Behavior-group numbers below identify scope/owners, not a sequential implementation order. Execute this dependency DAG with implementation prerequisites distinguished from integration/qualification exits: an exit consumes real staged components and does not make an independent implementation wait unless the row says so. Each named split is part of its owning group, not another specification or a partial product. Freeze a contract before its consumers change, migrate callers at the integration that activates their replacement, and remove old implementations only after replacement evidence from the real staged application. Temporary internal build states are not supported hybrids; no compatibility dispatcher or dormant fallback is added.

In ordinary mode retain the selected installation's normal project/user/site libraries after it; retain explicit project-isolated mode using `.alder/library` or the project's renv library, with no accidental user-library leakage. Running, analysis and package operations fail with that error; the renderer does not wait for kernel readiness to show cells. CLI `check`/`run` fail rather than claim success; MCP inspection remains available with capability state. Separate document readiness from execution readiness in the shared snapshot.
- Canonical commands are `alder [NOTEBOOK.R]` (desktop), `alder NOTEBOOK.R --browser` (open browser), `alder NOTEBOOK.R --headless` (foreground server), `alder mcp NOTEBOOK.R` (stdio), `alder check NOTEBOOK.R`, `alder run NOTEBOOK.R`, and `alder publish NOTEBOOK.R --output FILE.html`. Default bind is `127.0.0.1:0`; missing path in desktop creates an unsaved document. Explicit nonexistent `.R` with an existing writable parent opens a new unsaved-to-disk document; directories, other file types and missing parents fail without creating directory trees. `check`, `run`, `publish`, and `mcp` require a file path; no directory/gallery interpretation.
- `check` returns graph/analysis diagnostics without evaluating source; exit 0 means no blocking diagnostic, 1 means notebook/runtime failure, 2 means invalid CLI usage. `run` executes through the same Ark/controller and emits structured final status, not a second R evaluator; interrupt exits 130. `publish` consumes current settled outputs, never runs source implicitly. Logs go to stderr; stdio MCP stdout is protocol-only. For --browser/--headless the attaching CLI emits exactly one bounded newline-delimited stdout JSON record `{type:"host.ready",origin,epoch,capabilities}` as its first and only application stdout record, after authenticated document readiness, whether owner creation or joining. Smoke/latency drivers consume it. The detached host uses a private readiness pipe/registry, and Electron uses SessionConnection, not public stdout. No readiness record is emitted by mcp/check/run/publish; logs remain stderr and no credential appears in readiness.
- Joined check/run/publish observe the owner's committed in-memory document, not an independently reopened disk copy; final JSON includes epoch, documentRevision, dirty, disk (group 3), operation and result/error. check exits 0 only with no blocking diagnostics and otherwise 1; run/publish exit 0 only on terminal success, 1 for notebook/runtime/busy/conflict/tool/output failure, 2 for usage; interrupted run exits 130 after causal settlement. A busy owner rejects run_in_progress before committing run changes; no implicit queue/retry or new wait flag. A newly created check starts analyzer only; run starts analyzer/kernel and dispatches exactly one all-cells run; all verbs release only their own lease. Hold an explicit --headless --no-run lease for repeatable CLI run then publish of settled outputs; cold publish fails publish_not_ready and never evaluates. --browser opens a one-use ticket URL then releases its launch lease after the browser attaches; --headless holds its lease until signal. Failed browser launch releases its lease and returns typed failure. --help/--version/--host-info are document-free and R-free; --host-info emits validated artifact/protocol identity JSON, never registry secrets.
- Keep application shutdown idempotent and drain server/controller/Ark/analyzer/LSP/package jobs using the current close logic and the native containment contract below. Fail startup atomically: release partially started children and temporary artifacts. Remove R subprocess supervision and inherited stdin ownership, not the existing child cleanup guarantees. Verification: V1 and V8.
- The detached host, not Electron/CLI/MCP, owns execution-child containment. The monitor/adapter performs process cleanup only, no notebook evaluation/controller or restart policy. Record child process start identity as well as PID to avoid PID-reuse kills. Graceful close requests protocol shutdown then bounded termination; hard host death must also retire children, not rely on JavaScript finally. Keep Jupyter control-channel interrupt, qualified on native Windows/macOS; do not emulate successful interruption with process termination or use clients' process-tree killers on a live shared host.

Extend snapshot runtime with `documentReady:boolean` and `executionBlockedReason:HostError|null`; Engine startup rejection updates that state while the HTTP/document host stays alive. ### 2. Give TypeScript exclusive ownership of notebook bytes and application configuration

- Port the physical-record codec in `R/notebook.R` into new `host/src/notebook.ts`. Reuse the `SourceCell`/`SourceNotebook` model in `services.ts` and the record/source-map shapes in `lsp.ts`; consolidate those declarations here rather than retaining parallel models. Export `parseNotebook(bytes: Uint8Array, path: string | null): NotebookDocument`, `serializeNotebook(document: NotebookDocument): Uint8Array`, and `reconcileNotebook(document: NotebookDocument, source: SourceNotebook): NotebookDocument`. Reuse existing document-position functions in `lsp.ts` against this sole record model.
- Represent records as immutable original byte slices plus decoded text, EOL and kind. Untouched records serialize from their original bytes; allocate rewritten bytes only for edited records. Preserve UTF-8/BOM behavior, CRLF/LF/CR mixtures, missing final EOL, header and delimiter spelling, blank lines, duplicate option positions, unknown options and unrecognized tags. ## Assumptions and contingencies

- Installed R, rather than a bundled interpreter, is the selected product model. The initial explicit supported ABI is R 4.6.x; selecting another R minor remains an actionable unsupported-runtime error until a matched helper payload is built/qualified. Normal user/project packages remain usable; Alder does not own or silently upgrade the user's R installation.
- Desktop is the default human launch; browser mode and headless MCP remain complete supported deployments. Electron main attaches to the detached standalone bundled-Node host whose lease set owns its lifetime, rather than embedding the controller in Electron, preserving identical host/native dependencies and process-sharing behavior for GUI-first and agent-first use.
- The R helper API is intentionally narrowed to ui/out/cache with no launch shim; gallery, remote-controller facade, conversion matrix, alternate exporters and offline evaluator are removed. Local app/output layout and all core rich outputs are retained. MCP is release-essential; ACP and speculative collaboration/parallel evaluation do not acquire implementation files.

- Use the named minimal Ark patch against the pinned tag even if an upstream public publisher appears later; changing the kernel version/API is a separate deliberate dependency update. If the patch's native API cannot load or passes an invalid startup probe, fail runtime readiness and keep document editing available; never fall back to private hooks or HTML comments.
- If code signing secrets, notarization credentials or native runner access are unavailable, build and exercise every reachable artifact and mark the exact external release qualification unavailable. Do not substitute a cross-compiled package or Chrome run for a native installed/Electron acceptance claim.
